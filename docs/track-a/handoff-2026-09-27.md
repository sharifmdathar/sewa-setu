## Decisions already taken (keep them, don't re-litigate)

- Check ownership split: C1 = name/ID divergence, C4 = declared vs stated amounts **excluding**
  whole-decimal-zero gaps, C5 = duplicate sha256 + those order-of-ten gaps. `rules/numeric.py`
  `is_power_of_ten_ratio` is the discriminator; this is what keeps ground-truth labels unambiguous.
- C2 does **not** warn about far-future expiry dates (removed: the corpus legitimately issues
  10-year documents, so it was a false-positive generator). It only fails on expired / issued-in-the
  future / expiry-before-issue, and warns on an implausible issuing authority.
- `asOf` is an input to `ScrutinyInput`; the corpus uses the fixed `2026-06-30`. The live API (A7)
  passes today's date.
- Risk scoring is **not** implemented in the agent. The report still needs `riskScore` +
  `recommendation` to be contract-valid, so `report.py` should carry a small provisional
  weighted-sum of failed/warned check weights — write it, but expect A6's
  `pipeline/fraud/scorer.py` to supersede it, at which point the provisional code gets deleted
  (no shim).
- `.env.example` keys: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` (30 s timeout, 2 retries).
